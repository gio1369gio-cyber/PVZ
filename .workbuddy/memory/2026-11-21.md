## 修复 PVZ 模组 5 个 bug

1. **水盆水生植物枯萎（问题5）**：`PlantEntity.shouldWilt` 水生分支增加 WATER_POT 方块豁免，避免放在水盆上的水生植物被判定枯萎。

2. **ScreenDoor 只有下半部分（问题6）**：`ScreenDoorItem.useOn` 改为走 DoorBlock 标准双块放置（`getStateForPlacement` + 手动放上半块 + `setPlacedBy`），修复半截门。

3. **子弹跳过僵尸防具（问题4）**：`SweptHitResolver.resolve` 命中 MultiPartEntity（防具部件）时保留部件作为 target（不再映射宿主）；`BulletImpacts.dealDamage` 放宽为接受 Entity，对非 LivingEntity（part）直接调 hurtServer；`effectFromVariant` 增加 resolveLivingTarget 把 part 效果施加到宿主。使 `PVZHealthPartEntity.hurtServer` 的 setDefended/hitDefence 外层防御分流生效。

4. **内层升级外层退化（问题8）**：`PlantEntity.mergeUpgradeDataFrom` 外层转移时重新调用 `placeOn(this, sunCost)` 重建宿主绑定，再恢复实际剩余防御生命，避免 initAttributes 把外层防御重置为 0。

5. **makeSuperMode 先外层后内层（问题9）**：`PlantEntity.onSuperStart` 把外层植物 super（`p.onSuper(this)`）移到内层自身强化之前执行。

编译验证：`./gradlew compileJava` 通过（仅过时 API 提示）。

## 第五轮修复（棱镜草超级模式逻辑）

根据运行日志定位两处问题并修复：

1. **大招每 tick 重复攻击刷屏**：`SuperAttackGoal.tick` 攻击后只 `setTarget(null)` 未停止 goal、未重置 attackTime；targetSelector 下一 tick 立即重填 target → `canUse` 又 true → 重新蓄力攻击，导致 super 模式 200 tick 内反复攻击。修复：攻击后调用 `this.grass.setSuperTime(0)`（触发 plantTick 结束 SUPER 状态）+ `this.stop()`，使一次 super 只攻击一次。

编译验证：`./gradlew compileJava` 通过（仅过时 API 提示）。

## 本轮（指南针错误材质帧 + 保龄球高低差悬空）

1. **指南针有一帧错误材质**：根因是 `PvZItemModelRules.gardenCompassModel()` 里 range_dispatch 的 threshold 用了 `i+0.5`（0.5~31.5）。`RangeSelectItemModel` 语义是「取最后一个 threshold ≤ value 的 entry」，value = property×32 ∈ [0,32]；当指南针指向正北（property≈0，value<0.5）时 `lastIndexLessOrEqual` 返回 -1，落到 null fallback（`ItemModelUtils.rangeSelect` 无 fallback 重载）→ 缺省/错误材质。修复：threshold 改为 `i`（0~31），覆盖完整 [0,32] 区间（最后一帧 frame15 对应 threshold 31.0 覆盖 [31,32]）。重新 `runData` 生成 JSON 验证通过。

2. **保龄球高低差悬空**：`AbstractBowlingProjectile` 原为 `setNoGravity(true)` + 移动 Y 分量恒 0，跨高低差地形时在空中滚动。修复：`tickBowlingMove` 水平移动后调用新增的 `snapToGround()`，按球体水平投影向下扫描找支撑面（`findGroundY`，最多 32 层）；球底高于支撑面（下坡/悬崖）用 `fallVelocity` 累积重力渐进下落，低于/等于支撑面（上坡/台阶）直接抬升贴地；下方无方块（虚空）持续下落。`fallVelocity` 纳入 NBT 持久化。GiantNut（2.5×2.5）通过 `getBbHeight()/getBbWidth()` 通用适配。

编译验证：`./gradlew compileJava` 通过；`./gradlew runData` 成功（指南针 threshold 已更新为 0~31）。
